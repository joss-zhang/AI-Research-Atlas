# AI Research HTML

把一次研究任务变成仓库中可追溯、可关联、可直接阅读的 HTML 成果。研究质量和知识组织优先于页面数量。

## 先确定任务边界

从用户请求中提取：研究问题、目标读者、时间范围、行业或技术范围、必须回答的问题、期望深度和交付位置。已有对话足以确定这些信息时直接执行；只有缺失信息会实质改变研究结论或目录位置时才向用户确认。

本技能适用于：

- 人工智能概念、模型、智能体及应用研究；
- AI 汽车、智能座舱、智能驾驶和汽车产业链研究；
- 高质量数据集、数据治理与可信数据空间研究；
- 数字化、智能化和数智化研究；
- 论文精读、资源索引、学习教程和行业比较。

简单修改现有页面的错别字、样式或链接时，不必重新执行完整研究流程，但仍需完成相关验证。

## 工作流程

### 1. 理解仓库

完整阅读根目录 `README.md` 和 `AGENTS.md`。使用 `rg --files` 获取真实目录与文件，不依据 README 中的愿景假设文件已经存在。

检查：

- 相同或近似主题是否已有页面；
- 目标目录是否有更具体的规则；
- 工作区是否存在用户未提交的修改；
- 根导航页的数据结构和已有分类方式。

### 2. 选择唯一主目录

依照 `AGENTS.md` 的目录路由确定主目录：

- 论文研究进入 `01-papers/`；
- 通用概念、数据和数智化方法进入 `02-concepts/`；
- 原理验证进入 `03-code/`；
- 资源整理进入 `04-resources/`；
- 学习记录进入 `05-journals/`；
- 汽车与 AI 的行业交叉研究进入 `06-ai-automotive/`。

主题同时横跨多个方向时，按主要研究问题确定唯一主目录，并使用相关研究链接表达交叉关系。不要复制内容。

### 3. 建立研究问题与证据计划

先写出内部研究提纲，再收集资料。提纲通常覆盖：

1. 问题为什么重要；
2. 核心概念及边界；
3. 工作机制或价值链；
4. 主流方案与深度比较；
5. 典型案例和可执行方法；
6. 风险、限制与争议；
7. 有判断力的结论。

为每个关键结论记录需要的证据类型。比较产品或方案时先建立统一维度，避免按厂商宣传材料逐家复述。

### 4. 研究本地与外部资料

先阅读仓库内的相关页面、资料索引和实验记录，再检索外部信息。

外部研究遵循以下顺序：

1. 论文、标准、法律政策、政府文件；
2. 官方技术文档、产品文档和工程博客；
3. 企业技术报告、财报和公开演讲；
4. 可信行业机构与专业媒体；
5. 二手综述仅用于发现线索或补充背景。

对于市场规模、产品能力、政策、价格、组织变动和其他时效性事实，核对信息日期并优先使用当前材料。关键结论尽量使用两个独立来源交叉验证。记录无法验证、存在口径差异或仅来自供应商自述的内容。

### 5. 综合分析而非搬运

把资料转化为清晰的因果链、比较框架和决策含义：

- “事实”给出直接证据；
- “观点”注明是谁的主张；
- “推断”说明证据如何支持判断；
- “预测”给出前提、时间范围和可能失效的条件。

不要用引用数量代替分析。删除不能帮助回答研究问题的资料。

### 6. 设计页面结构

围绕读者的学习路径组织页面，而不是套用固定组件。最低信息结构包括：

- 标题、解释性副标题和研究价值；
- 更新时间、研究范围或口径；
- 摘要或关键发现；
- 分层正文；
- 关键比较、流程、关系或案例；
- 风险与限制；
- 明确结论；
- 相关研究；
- 来源与延伸阅读。

只在表格、流程图、关系图或数据图能够显著降低理解成本时使用可视化。所有图形都要有文字说明，不能只靠颜色表达含义。

### 7. 生成单文件 HTML

创建带有 `<!doctype html>`、`lang="zh-CN"`、UTF-8、viewport、description 和准确 title 的完整文档。

技术要求：

- CSS 与必要 JavaScript 全部内嵌；
- 不使用 CDN、网络字体、外部 API 或安装依赖；
- 使用语义化 HTML 和正确标题层级；
- 提供跳到正文链接和清晰的 `:focus-visible`；
- 正文基准字号不小于 16px；
- 桌面端可使用多列，手机端回流为清晰单列；
- 防止长链接、表格、代码和图形造成页面级横向溢出；
- 动画只用于帮助理解，并尊重 `prefers-reduced-motion`；
- 所有交互在没有网络的本地文件环境中工作；
- 可见文案使用自然、准确的简体中文。

视觉选择要与具体主题有关。通过字号、字重、对齐、留白、细分隔线和少量强调色建立层级，避免卡片墙和无意义装饰。

### 8. 建立知识关联

在页面中增加少量高相关的内部链接，并简要说明关联原因。使用从当前文件出发的相对路径。若新成果为已有页面提供了重要前置知识或延伸案例，在不干扰用户修改的前提下补充返回链接。

### 9. 更新根导航页

打开根目录 `index.html`，在内嵌 `PAGE_INDEX` 数组中新增或更新记录。记录的标题、摘要、日期、方向、类型和关键词必须与真实页面一致。

执行全仓库 HTML 清点，确保：

- 所有研究 HTML 都有且只有一条记录；
- `index.html` 自身、临时预览和测试查看器没有被收录；
- 记录路径从仓库根目录出发并真实存在；
- 页面移动或重命名后旧路径已被修正。

### 10. 验证后交付

至少完成以下检查：

1. 用 HTML 解析器检查基本结构；
2. 检查内嵌 JavaScript 语法或浏览器控制台错误；
3. 检查全部内部链接和导航记录的目标文件；
4. 检查是否意外引入外部依赖；
5. 在桌面和手机视口验证布局、字号、裁切与横向溢出；
6. 测试搜索、筛选、目录或其他关键交互；
7. 查看工作区差异，确认没有覆盖用户内容。

最终说明创建或修改了哪些文件、研究成果位于哪里、导航是否更新、执行了哪些验证。不要用冗长的设计过程替代交付结果。

## 重复与失败处理

- 已有页面完整覆盖请求时，优先扩展或更新原页面，不创建标题略有不同的重复版本。
- 已有页面包含用户正在进行的修改时，先保留并围绕修改工作；无法安全合并时说明冲突。
- 权威资料不足时降低结论强度，标记证据缺口，不用看似精确的数据填补空白。
- 本地浏览器无法运行时，仍执行结构、链接和静态检查，并明确未完成的视觉验证。
- 导航数据与磁盘文件不一致时，以真实研究文件为准修正导航，但不得擅自删除研究文件。

## 典型触发示例

**示例一**

用户：“深入分析端到端自动驾驶的技术路线，做成可以直接打开的网页，放到合适目录。”

结果：归入 `06-ai-automotive/`，研究最新权威资料，生成单文件 HTML，关联相关汽车研究并更新根导航页。

**示例二**

用户：“系统讲清楚高质量训练数据集如何建设，要有指标、流程、案例和风险。”

结果：在 `02-concepts/` 下选择或创建数据主题子目录，完成证据化教程 HTML，并登记到导航页。

**示例三**

用户：“精读这篇多模态论文，说明核心贡献、方法、局限和对座舱的启发。”

结果：论文主体归入 `01-papers/`，通过内部链接关联 `06-ai-automotive/` 的应用主题，输出 HTML 并更新导航。
