01 / 概念图

一张图看懂：从观测到行动

SOH 是电池相对额定容量或功率能力的健康指标；“异常”是一个需要业务定义的动作标签，而不是天然存在的真相。二者共享特征，却服务不同决策。

车辆观测

电压、电流、温度、SOC、充放电功率、里程、环境和软件版本。

特征与标签

窗口统计、斜率、温差、内阻代理；SOH 连续值或异常事件标签。

模型族

规则 → 逻辑回归 → 决策树/随机森林/梯度提升；聚类与 PCA 辅助理解。

评估证据

时间/分组交叉验证、误差分层、校准、置信区间和反事实边界。

动作与责任

BMS 限功率、提醒复检、售后工单或继续观测；每个动作需要安全门槛。

最重要的区分：预测问题问“接下来会怎样”；因果问题问“如果我们改变充电策略或维修动作，会发生什么”。高分预测不自动等于有效干预。

02 / 算法拆解

八个概念，放回电池问题里理解

回归

预测一个连续量

令 y 为 SOH（0–100），模型学习 f(X)≈y。常见损失是平方误差，业务更关心 MAE、RMSE、分位数区间和低健康区间的误差。关键：不能随机打散同一电池的相邻循环，否则未来信息会泄漏。

分类

判断是否触发动作

令 y∈{0,1} 表示未来 7 天是否需要检查。逻辑回归输出 p(y=1|X)，阈值决定告警。异常稀少时，PR-AUC、召回率、每车每月误报数往往比准确率更有意义。

树模型

用分裂表达非线性

决策树递归选择特征阈值，随机森林用多棵树降方差，梯度提升逐步纠正残差。它们能表达“高温且快充频繁”这类交互，但深树容易记住电池编号、车型或采集批次。

聚类

没有标签时找运行群体

K-means 以距离最小化形成 k 个簇，DBSCAN 以密度识别噪声。可用于发现城市/高速、冬季/夏季或快充/慢充工况；簇不是故障原因，必须回到物理与业务解释。

降维

压缩结构，不制造证据

PCA 用中心化后的奇异值分解投影到低维空间，适合去冗余、可视化和探索漂移。主成分的方向可解释性有限；必须只在训练折拟合，再作用于验证/测试折。

偏差—方差

解释“简单错”还是“复杂不稳”

高偏差模型在训练和测试都差；高方差模型训练好、换电池或换季节就掉。增加特征、正则化、更多样本、限制树深或集成，都是在两者间取舍。

交叉验证

估计换数据后的表现

普通 K 折假设样本近似独立同分布。车辆数据要优先考虑按电池/车辆分组，按时间滚动，或两者嵌套；调参不能窥视最终测试集。

校准与因果

让概率能被信任，也知道不能推因果

校准要求预测 0.8 的样本约有 80% 真的异常；可用 sigmoid 或 isotonic，但要有独立校准折。因果意识要求画出温度、驾驶、充电策略、维修和 SOH 的关系，避免把相关当成“改动后一定有效”。

回归：MAE = (1/n) Σ |yᵢ − ŷᵢ|；RMSE = √[(1/n) Σ (yᵢ − ŷᵢ)²] 分类：logit(p) = β₀ + βᵀx；阈值 t 决定“告警 / 不告警” 校准：在概率分箱 b 中，平均预测概率 ≈ 实际阳性率 偏差—方差：期望测试误差 ≈ 偏差² + 方差 + 不可约噪声

03 / 案例全过程

案例：预测 SOH，同时预警异常

下面的数值、字段和实体是教学设定。真实项目应由电芯试验、BMS 估计策略、售后定义和法规责任共同确定标签，不能直接把公开数据的结论搬到量产车。

01

把业务目标写成两个任务

回归：在未来一个诊断窗口估计 SOH，供剩余里程、保修筛查和电池梯次利用参考。
分类：判断未来 7 天是否需要复检，供售后分流。先写动作成本：漏报可能带来安全与停驶风险，误报消耗工位与用户信任。

02

建立数据契约与标签定义

最小字段包括 battery_id、vehicle_id、timestamp、voltage_mean、voltage_delta、current_mean、temperature_max、soc_start/end、charge_type、mileage、software_version 和 measured_capacity。SOH 标签需注明测试协议、参考容量、测量误差和时间点；异常标签需注明事件窗口、确认方式、是否受维修策略影响。

03

做数据质量检查，先找泄漏

检查单位、采样频率、时间逆序、重复事件、传感器饱和、缺失模式和版本漂移。禁止把“维修后故障已清除”“未来一次容量测试”或人工筛选结果放进特征。按 battery_id 分组查看同一电池是否同时出现在训练和测试。

04

从物理启发的特征开始

从窗口内提取温度峰值与持续时间、单体电压离散度、充放电倍率、库仑计量差、内阻代理、SOC 区间、快充次数、环境温度和循环序号。每个特征记录计算窗口、单位、缺失处理和是否可在车端实时获得。

05

设计分层切分与交叉验证

先按时间保留最后一段作为最终测试；训练阶段使用按电池分组的 GroupKFold，若要模拟上线则使用滚动 TimeSeriesSplit，并设置 gap 避免相邻窗口污染。所有标准化、PCA、特征选择和校准都只能在训练折拟合。

06

先跑规则基线

例：当电压离散度 > 40mV 且温度峰值 > 45℃ 时告警；当 SOH 低于 80 时建议复检。规则的价值不是一定最优，而是让团队知道现有经验、阈值稳定性和误报结构。

07

再跑逻辑回归与树模型

逻辑回归提供可解释的线性基线与概率输出；浅层树展示非线性分裂；随机森林/梯度提升捕捉交互但增加复杂度。调参范围要小且预先登记，避免以测试集挑模型。

08

按“误差—概率—业务”三层评估

SOH 回归看 MAE、RMSE、P90 绝对误差、低 SOH 分层和跨电池泛化。异常分类看召回、精确率、PR-AUC、每车每月告警数、告警提前量和校准曲线。最后把误报、漏报、延迟、算力与售后成本放入同一决策表。

09

做聚类与 PCA 的“诊断性”实验

用 PCA 观察不同车型、季节和工况是否形成结构；用 K-means 或 DBSCAN 标出异常工况候选，再回看原始曲线。它们用于发现数据分层和采样盲区，不直接替代有标签的安全告警。

10

加入校准、漂移与不确定性

如果告警概率用于排队和资源分配，必须在独立校准集上验证可靠性。监控车型、季节、软件版本、温度区间的特征分布与召回变化；对分布外样本降级为“继续观测”或“人工复检”。

11

问清楚“改变什么会怎样”

如果业务想知道“降低快充功率是否会改善 SOH”，这是干预问题。充电策略往往由温度、用户习惯和车辆版本共同决定，存在混杂与选择偏差。应画因果图、寻找自然实验或设计受控试验；预测模型的特征重要性不能作为干预证据。

12

把模型接进动作与责任链

车端只做轻量特征和安全相关降级，云端做训练与群体分析；告警生成工单前要经过规则门、版本门和人工确认。上线包必须包含模型版本、训练数据范围、阈值、回滚方式、责任人和复盘周期。

04 / 模型比较

规则、逻辑回归、树模型：如何做选择

以下是教学场景下的比较框架，不是声称某模型在真实车辆上必然胜出。模型选择优先服从标签质量、时间切分、解释要求和错误成本。

基线 A

规则阈值

物理和售后知识显式写出，延迟低、易审计、无需训练。缺点是阈值脆弱，难以表达多变量交互，换车型需要重新标定。

适合：安全兜底 / 冷启动 / 回滚

基线 B

逻辑回归

用线性加权和输出概率，系数方向便于审查，适合作为稳定的第一版分类器。缺点是非线性和交互需要手工特征，强相关特征会使系数不稳定。

适合：可解释告警 / 概率排序

候选 C

树模型

树和集成能捕捉阈值、交互与缺失模式，通常适合结构化车辆数据。缺点是可能记住车型或时间，概率往往需要额外校准，模型体积与版本管理更复杂。

适合：复杂关系 / 离线筛查

05 / 100 行以内 Toy 实验

用一份合成数据跑通三种分类器

这段代码故意保持小而透明：生成“温度峰值、电压离散度、快充次数、循环序号”四个特征，按时间切分，比较规则、逻辑回归和随机森林的 PR-AUC、召回与校准误差。它用于理解实验结构，不替代真实 BMS 数据。

toy_battery_ml.py · 约 70 行 · 需要 numpy / scikit-learn教学代码
import numpy as np
from sklearn.model_selection import TimeSeriesSplit
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import average_precision_score, recall_score, brier_score_loss

rng = np.random.default_rng(7)
n = 900
cycle = np.arange(n)
temp = 25 + 0.012 * cycle + rng.normal(0, 3, n)
spread = 12 + 0.018 * cycle + 0.35 * np.maximum(temp - 38, 0) + rng.normal(0, 3, n)
fast = rng.poisson(2 + cycle / 450)
z = -5.2 + .08 * temp + .055 * spread + .18 * fast
y = (rng.random(n) < 1 / (1 + np.exp(-z))).astype(int)
X = np.c_[temp, spread, fast, cycle]
cut = 650
Xtr, Xte, ytr, yte = X[:cut], X[cut:], y[:cut], y[cut:]

def rule(x):
    return ((x[:, 0] > 42) & (x[:, 1] > 24)).astype(int)

models = {
    "rule": None,
    "logistic": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "forest": RandomForestClassifier(n_estimators=160, min_samples_leaf=8,
                                      random_state=7, class_weight="balanced")}
for name, model in models.items():
    if name == "rule":
        pred, prob = rule(Xte), rule(Xte).astype(float)
    else:
        model.fit(Xtr, ytr)
        prob = model.predict_proba(Xte)[:, 1]
        pred = (prob >= .5).astype(int)
    print(name, "PR-AUC=%.3f recall=%.3f Brier=%.3f" % (
        average_precision_score(yte, prob), recall_score(yte, pred),
        brier_score_loss(yte, prob)))

# 只在训练段上做滚动验证，防止把未来样本带进调参
tscv = TimeSeriesSplit(n_splits=4, gap=12)
print("folds", [(len(a), len(b)) for a, b in tscv.split(Xtr)])

读代码时要问：标签生成机制是否泄漏？阈值 0.5 是否符合成本？为什么 Brier 不能单独代表排序能力？如果随机打乱样本，结果为何可能虚高？

06 / 数据卡与模型卡

把“可用”写成别人能检查的事实

数据卡：电池健康度教学集

  • 用途：学习特征工程、时间切分和评估，不用于安全控制。
  • 来源：合成数据或经授权的实验/车队数据；记录采样协议、车辆和电芯化学体系。
  • 单位：电压 V、电流 A、温度 ℃、里程 km、容量 Ah；禁止隐式换算。
  • 标签：SOH 的参考容量、测试方法、测量误差和时间窗；异常的确认标准。
  • 缺失与偏差：冬夏、车型、快慢充、软件版本和传感器故障的覆盖情况。
  • 权限与保留：VIN 脱敏、最小访问、用途限制、删除与审计记录。

模型卡：SOH/异常双模型

  • 版本：模型、特征、阈值、代码和训练数据哈希必须绑定。
  • 输入：只使用预测时可获得的窗口特征；列出缺失处理和范围检查。
  • 性能：按电池、车型、季节、版本分层报告；给出置信区间和校准曲线。
  • 限制：分布外、传感器失真、标签延迟、未覆盖电芯体系时降级。
  • 人机边界：模型只建议复检或限制策略，不直接绕过 BMS 硬保护。
  • 变更：数据漂移、召回下降或供应商变更触发再评估。

08 / 工程交付

从 Notebook 走到可负责的系统

架构决策记录（ADR）

背景车端算力、网络和数据权限受限；售后需要提前量和可解释证据。
决定车端计算窗口特征与硬规则，云端训练和群体分析；逻辑回归作为首版概率模型，树模型只作为离线 challenger。
理由首版优先可审计、可回滚和跨车型迁移；先用模型发现价值，再以数据证明复杂模型的增益。
代价车端特征能力受限；云端存在断网延迟；需要维护两套版本与特征契约。
复审触发新车型、软件版本、召回率下降、校准漂移、温度覆盖变化或供应商更换。

运行手册（Runbook）

发现

监控数据新鲜度、缺失率、特征范围、漂移、告警率和模型延迟。

分诊

按车辆、软件、车型、地区和传感器版本定位；先排查数据契约再怀疑模型。

降级

超出范围时停止自动动作，回退规则或人工复检；保留证据和用户提示。

复盘

修复后重放历史窗口、更新模型卡、补充长尾样本并记录责任人与期限。

安全案例（Safety Case）

主张

模型只用于风险分层和复检建议，不替代 BMS 硬保护，不直接控制高压回路；超出数据范围时必须安全降级。

证据

需求追踪、数据/模型卡、分层评测、校准曲线、故障注入、回滚演练、人工确认流程和版本审计。

产品决策备忘录

建议先在一款车型、一个区域和售后复检场景试点，不直接开放自动限功率。
成功条件召回率、误报量、提前量、工单闭环率、用户投诉、端到端延迟和校准误差同时达标。
停止条件安全相关漏报未能解释、数据版本无法追溯、跨季节性能显著下降或模型无法回滚。

在电池健康度问题上，最强的第一步通常不是更复杂的模型，而是更可信的标签、更诚实的切分和能被业务执行的评估。
