02 / 核心概念 · 2026.08.11

深度学习与多模态输入：把座舱信号变成可信决策

以驾驶员监测（DMS）与座舱意图识别为贯穿案例，逐层拆解反向传播、CNN、Transformer、表示学习、迁移学习和音视频融合，并把“模型分数”接到真实车载系统的评测、降级与责任边界。

阅读价值
你会看到一条完整链路：从像素、波形和车辆上下文，到状态估计、意图候选、混淆矩阵、误报成本，再到边缘部署和安全运行手册。

先看变化：从“会分类”到“敢上线”

DMS 的目标不是判断一个人的性格、情绪或健康状况，而是在明确定义的驾驶任务中，识别可观测的风险候选，并让上层策略决定是否提醒、何时提醒、如何降级。NHTSA 将分心拆为视觉、认知和手动维度；Euro NCAP 2026 已将 Occupant Monitoring、Driver Engagement 和 Driver Monitoring dossier/test procedure 列为安全驾驶协议组成部分。

单模态分类器

只看一帧脸部图像，容易把夜间、墨镜、口罩、逆光当作“状态变化”；准确率高也可能在连续驾驶中频繁误报。

多模态状态估计

把连续视频、音频、方向盘/车速/HMI 事件对齐，输出状态、意图、置信度与“不可用”，而不是被迫输出正常。

平均准确率

把四类样本混成一个数字，掩盖最危险的漏报，也掩盖每小时几十次提醒带来的驾驶员适应和关闭功能。

成本与场景评测

用混淆矩阵、每驾驶小时误报、首次告警延迟、分层召回和缺失模态策略共同决定是否可上线。

全局逻辑路径

五步把“信号”变成“可控动作”

1. 采集与对齐红外相机、麦克风、车辆与 HMI 事件
2. 表示学习CNN、音频编码器、预训练特征
3. 时序融合Transformer 建模连续行为和上下文
4. 评测与决策混淆矩阵、成本、置信度、分层切片
5. 安全运行降级、监控、人工确认和证据留存

01 / 机制

六个概念，放回同一辆车里理解

反向传播：误差如何回到参数

前向计算得到预测 ŷ，损失函数比较标签 y 与预测；反向传播用链式法则计算每层参数对损失的梯度，优化器再按 θ ← θ − η∇θL 更新。DMS 中，一个“困倦候选”标签的错分会通过分类头、时序层、视觉编码器逐层传回。

  • 先检查标签是否可观测、时间窗是否一致，再谈梯度。
  • 梯度消失/爆炸、类别不平衡和错误增强，会让训练曲线漂亮而线上失真。

CNN：把局部空间结构变成特征

卷积核在局部感受野内共享参数，逐层捕捉眼睛、嘴部、头部姿态和遮挡边缘；池化扩大有效感受野，残差连接让更深网络更易优化。CNN 对每帧高效，但单独使用时难以理解“连续 4 秒闭眼”这种事件。

工程要点：输入裁剪、红外/可见光域差异、帧率、摄像头位置和量化后的延迟必须同时验证。

Transformer：用注意力连接时间上下文

对序列中的每个 token 生成 Q、K、V，注意力权重由 QKᵀ 决定，模型可以让当前帧关注更早的眨眼、头转和语音片段。原始 Transformer 只用注意力、去掉循环和卷积，换来更强的并行训练能力；车端却要额外面对窗口长度、内存和实时性。

工程要点：使用固定窗口或因果注意力，限制 token 数，明确“未来帧不能泄漏到当前告警”。

表示学习：先学“可复用的坐标系”

把视频、音频或车况片段编码为向量，让相似驾驶状态更接近。自监督/对比学习可利用无标签行程，但模型可能学到司机身份、光照或车型偏差；表示好看不代表任务标签可用。

验证方式：线性探针、跨司机/车型/夜间切片、最近邻审查，以及删除敏感属性后的性能变化。

迁移学习：从通用预训练到车内域

先加载通用视觉或音频编码器，再冻结特征做线性探针，最后用小学习率微调任务头和部分骨干。每一次域迁移都要重新检查分布、隐私和失效模式，不能把公开数据集上的分数直接当成车规结论。

推荐顺序：冻结基线 → 小范围解冻 → 场景增量训练 → 回归全量与最差切片。

音视频融合：让模态互相校验

视频提供注视、头姿和闭眼线索，音频提供唤醒词、指令和说话人活动，车辆/HMI 提供速度、导航和操作上下文。早期融合信息丰富但对齐敏感；晚期融合更易降级；门控融合按质量和可用性动态分配权重。

边界：音视频只能支持事先定义的驾驶相关状态与意图候选，不应推断医疗诊断、人格或“真实情绪”。

02 / 贯穿案例

案例：驾驶员监测 + 座舱意图识别

产品问题在 60 km/h 以上，系统要判断“是否需要提醒驾驶员”，同时识别“接听来电、调整空调、开启导航”等座舱意图候选。

输出契约DMS 输出四类状态：正常、视觉分心、困倦候选、遮挡/不确定；意图模块输出候选、置信度、来源模态和是否需要用户确认。任何高风险动作都不由模型直接执行。

标签原则用时间窗标注“眼睛离开道路、持续闭眼、摄像头被遮挡、用户明确说出/触发某意图”，保留起止时间、标注者一致性和证据类型；不把“看起来疲惫”当标签。

数据切分按司机、车辆、行程和时间切分，禁止同一段视频的相邻帧跨越训练/验证/测试；单独保留夜间、逆光、墨镜、口罩、方言、噪声和摄像头遮挡切片。

模型演进

  1. 基线：规则（眨眼时长、头姿阈值）建立可解释对照。
  2. 单模态：轻量 CNN 提取帧特征，按窗口统计。
  3. 时序：Transformer 接收视觉 token、音频 token 和车辆上下文，使用因果窗口。
  4. 融合：质量门控决定视频、音频、车辆信号的权重，缺失时输出“不确定/不可用”。
关键判断

“置信度低”不是“状态正常”。对遮挡和传感器失效保留独立类别，才能让上层策略选择降级而不是被错误安抚。

环节输入/动作必须交付验收问题
采集IR 视频、音频、车速、方向盘、HMI 事件数据字典、采样率、同步误差、同意与留存策略能否追溯一条样本为何被采集、何时删除？
标注状态与意图按时间窗双人复核标签指南、争议样本集、标注一致性标签是否可由画面/音频证据支持？
训练CNN → 时序 Transformer → 门控融合实验配置、随机种子、数据/模型卡是否存在司机或行程泄漏？
车端量化、缓存、帧丢失和模态缺失测试延迟、内存、功耗、降级矩阵摄像头被遮挡时是否安全地“不判断”？
产品告警、二次确认、人工接管/暂停决策备忘录、运行手册、回滚条件误报是否会让用户关闭功能，漏报是否被策略兜底？

03 / Toy 实验

100 行以内：用合成多模态向量跑一遍融合

下面的实验只演示张量拼接、门控和成本敏感损失，不包含真实人脸或录音，也不代表车端模型性能。四个类别与案例契约一致，训练后打印混淆矩阵，便于继续替换成真实数据加载器。

import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

torch.manual_seed(7)
n, d, k = 1600, 12, 4
v = torch.randn(n, d); a = torch.randn(n, d); c = torch.randn(n, 4)
score = v[:, :4] + .7 * a[:, :4] + .3 * c[:, :4]
y = score.argmax(1)
ds = TensorDataset(v, a, c, y)
loader = DataLoader(ds, batch_size=64, shuffle=True)

class FusionNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.v = nn.Linear(d, 16); self.a = nn.Linear(d, 16)
        self.c = nn.Linear(4, 8); self.g = nn.Linear(40, 3)
        self.out = nn.Linear(40, k)
    def forward(self, v, a, c):
        v, a, c = torch.relu(self.v(v)), torch.relu(self.a(a)), torch.relu(self.c(c))
        z = torch.cat([v, a, c], 1); gate = torch.softmax(self.g(z), 1)
        z = torch.cat([v * gate[:, :1], a * gate[:, 1:2], c * gate[:, 2:3]], 1)
        return self.out(z), gate

model = FusionNet(); weight = torch.tensor([1., 4., 5., 2.])
opt = torch.optim.Adam(model.parameters(), lr=.003)
for epoch in range(12):
    for vb, ab, cb, yb in loader:
        pred, _ = model(vb, ab, cb)
        loss = nn.functional.cross_entropy(pred, yb, weight=weight)
        opt.zero_grad(); loss.backward(); opt.step()

cm = torch.zeros(k, k, dtype=torch.int64)
with torch.no_grad():
    for vb, ab, cb, yb in loader:
        p = model(vb, ab, cb)[0].argmax(1)
        for t, q in zip(yb, p): cm[t, q] += 1
print("rows=true, cols=pred\\n", cm)

读法：把 `weight` 改成你的业务成本，观察模型是否牺牲“正常”精度来减少危险漏报；再增加缺失音频/遮挡视频的样本，验证门控是否真的学会“不确定”。

05 / 交付物

把研究变成工程可交接的证据

数据卡

  • 来源：同意范围、采集设备、采样率、时间窗和删除策略。
  • 覆盖：司机/车型/地区/昼夜/天气/遮挡/音频噪声；列出缺口。
  • 标签：状态定义、意图定义、争议样本、标注一致性和泄漏检查。
  • 使用限制：不用于身份识别、医疗诊断、人格推断或无告知的个体画像。

模型卡

  • 输入与输出：模态、窗口、四类状态、意图候选、置信度与不可用。
  • 性能：总体与最差切片的混淆矩阵、成本、校准、延迟、内存、功耗。
  • 失效：夜间、逆光、遮挡、音频缺失、跨车型和跨版本漂移。
  • 禁止用途：不能替代驾驶员、医疗判断或安全策略，也不能直接执行高风险动作。

架构决策记录（ADR）

决定：车端优先，视觉 CNN + 固定窗口 Transformer + 晚期门控融合；原始人脸/音频默认不出车。

理由：能把单模态失败隔离，允许无音频/遮挡时降级，且更符合实时、隐私和可回滚要求。

代价：对齐、缓存和模型版本更复杂，必须维护模态可用性指标与回归集。

运行手册

  • 监控：帧质量、音频信噪、模态缺失率、端到端延迟、每小时告警数。
  • 处置：先区分采集/同步/模型/策略故障，再按版本、车型、场景回放。
  • 降级：相机遮挡或音频不可用时标记不可用，暂停高风险自动动作，保留人工确认。
  • 回滚：成本、最差切片召回、延迟或误报超过门槛即停止灰度。

06 / 安全与产品

安全案例与产品决策备忘录

安全主张

模型只提供有证据边界的状态/意图候选；最终告警由规则、置信度、车辆状态和人工确认共同决定。DMS 不是临床诊断，也不是对“注意力”的绝对测量。

证据包

场景覆盖矩阵、数据与模型卡、混淆矩阵、成本分析、最差切片、传感器失效测试、误报用户研究、隐私与留存审查、版本回滚记录。

首发范围

先做低风险的提醒和座舱建议：告警可解释、可暂停、可由用户确认；导航、空调等意图只生成候选，不直接执行跨域高风险动作。

停止条件

任一关键切片的危险漏报超限、每小时误报显著上升、模态缺失被误判为正常、端到端延迟破坏告警时序，立即停止扩大灰度。

核心结论

深度学习在座舱里真正的竞争力，不是把准确率再推高一个百分点，而是把多模态证据、错误成本、不确定性和降级动作一起设计成可验证的系统。

当模型只能说“我看到了什么、我有多确定、我现在是否不可用”，而策略层能据此谨慎行动，AI 才从演示能力变成可以被驾驶员信任、被工程团队维护的车载能力。
